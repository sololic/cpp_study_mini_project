# const 참조 vs 일반 참조 — 리터럴 허용 여부

---

## 📌 결론

| 종류 | 변수 | 리터럴(임시값) |
|:----:|:----:|:--------------:|
| 일반 참조 (`int&`) | ✅ | ❌ |
| const 참조 (`const int&`) | ✅ | ✅ |

---

## 📖 리터럴이란?

코드에 **직접 작성된 고정된 값**

```cpp
int a = 10;           // 10이 리터럴
double b = 3.14;      // 3.14가 리터럴
std::string s = "hello"; // "hello"가 리터럴
```

---

## ❌ 왜 일반 참조는 리터럴을 못 받나?

참조는 변수의 **별명** → 수정할 수 있어야 한다.

```cpp
int& ref = 100;  // 에러!
ref = 200;       // 만약 된다면? 고정값 100을 200으로 바꾼다는 말
                 // 100은 코드에 박혀있는 값 → 수정 불가
```

> 일반 참조는 "나 이거 바꿀 수도 있어" 라고 선언하는 것
> → 리터럴은 수정 불가능하므로 컴파일러가 거부 ❌

---

## ✅ 왜 const 참조는 리터럴을 받을 수 있나?

```cpp
const int& ref = 100;  // OK!
```

> const 참조는 "절대 안 바꿀게" 라고 보장
> → 리터럴도 안전하게 참조 가능 ✅

### 내부 동작 (컴파일러가 자동 처리)

```cpp
// 개발자가 쓴 코드
const int& ref = 100;

// 컴파일러가 내부적으로 처리하는 방식
int temp = 100;        // 임시 변수 생성 (자동)
const int& ref = temp; // 임시 변수를 const 참조로 연결
```

---

## 🔧 컴파일러란?

`.cpp` (사람이 읽는 코드) → 바이너리 (컴퓨터가 실행하는 코드) 로 변환해주는 프로그램

```bash
g++ references_test.cpp -o references_test
# [컴파일러]  [소스코드]      [출력 실행파일]
```

임시 변수 생성 같은 내부 처리는 컴파일러가 자동으로 해주기 때문에 개발자는 신경 안 써도 된다.
